# Методы и модели (методичка AITU, раздел 3.12)

Три метода (rule-based, нейросетевой, гибрид) × три задачи (NER, POS, морфология).
Для каждого метода ниже: **что делает → почему выбран → формулировка → допущения и их критика**.
Код, на который ссылается текст, — в `src/`. Данные и предобработка — `docs/data.md`.

| Метод | Задачи | Код | Файлы предсказаний |
|---|---|---|---|
| Rule-based | NER | `src/rules/ner.py` | `ner_rule.jsonl` |
| Rule-based | POS, морфология | `src/rules/morphology.py`, `src/rules/lexicon.py` | `pos_rule.jsonl`, `morph_rule.jsonl` |
| Нейросеть | NER; POS + морфология | `src/neural/` | `{task}_neural_seed{N}.jsonl` |
| Гибрид | все три | `src/hybrid/` | `{task}_hybrid_seed{N}.jsonl` |
| Оценка | все | `src/eval/` | `summary_3x3.csv`, `significance.csv` |

Принцип эксперимента: все методы обучаются/строятся только на **train**, параметры
подбираются только на **dev**, **test** используется один раз для итоговых чисел.
Сравнение — только внутри задачи, на одном и том же тесте.

## 1. Rule-based метод

### 1.1 Общая морфологическая инфраструктура (POS и морфология)

**Что делает.** Для слова $w$ анализатор порождает множество кандидатов-разборов

$$A(w) = \{(u, f, \ell, s, \text{src})\}$$

где $u$ — часть речи UPOS, $f$ — набор признаков FEATS, $\ell$ — лемма, $s$ — оценка правдоподобия,
src — источник. Источники по убыванию доверия:

| Источник | Оценка $s$ | Пример |
|---|---|---|
| пунктуация, числа (регулярные выражения) | 9–10 | `2014` → NUM NumType=Card |
| словарь словоформ из train | $6 + n(u,f \mid w)/n(w)$ | частотный разбор известного слова |
| словарь служебных слов (вручную) | 5 | `бізге` → PRON Case=Dat\|Number=Plur\|Person=1 |
| морфотактика (аффиксы) | $1.5 + 0.25\,|a| \pm$ бонусы | `кітаптарымызда` → основа + лар + ымыз + да |
| умолчание | 1.4 (NOUN), 2.6 (PROPN) | |

*Морфотактика имени* записана как произведение слотов: $\text{основа} + \text{PL}^{?} + \text{POSS}^{?} + \text{CASE}^{?}$.
Каждый слот — список алломорфов (сингармонизм, ассимиляция) с признаками; признаки цепочки — объединение
признаков слотов (`join_feats`). После притяжательного аффикса 3 л. падеж присоединяется через *-н-*
(`баласы-на`). *Глагольные окончания* (время, лицо, отрицание, причастия, деепричастия, герундий,
наклонения) — отдельный список; страдательный залог порождается приставкой *-ыл/-іл/-л/-н* к окончанию.
Бонусы: +1.5, если основа известна из словаря лемм train как глагольная (для глагольных разборов) или
именная (для именных); штраф −1 для однобуквенных глагольных аффиксов.

*Контекстные правила* (`RuleTagger`) меняют оценки: последнее слово предложения — вероятное сказуемое
(+1.5 финитным формам, −1 винительному падежу); финитные догадки не в конце предложения −0.8;
«мен» в начале предложения — местоимение, иначе союз; деепричастие перед вспомогательным глаголом +1.

**Решение.** $\hat{a}(w) = \arg\max_{a \in A(w)} s(a)$; POS = $\hat{u}$, морфология = $\hat{f}$.

**Почему так.** Казахский — агглютинативный язык: словоформа однозначно собирается из основы и
цепочки аффиксов, поэтому аффиксальный анализ — естественная основа правил. Доля слов dev/test UD-KTB,
отсутствующих в train, — 41–45%; без анализа аффиксов такие слова не разобрать. Множество кандидатов
(а не один ответ) нужно гибриду.

**Допущения и критика.**
1. *Алломорфы перечислены без строгой проверки сингармонизма* — правила перегенерируют разборы.
   Смягчается оценками и выбором самого длинного аффикса, но ошибки вида «основа на *-тан* принята за
   исходный падеж» остаются.
2. *Оценки $s$ — эвристика, а не вероятность.* Значения подобраны вручную на dev; test не использовался.
3. *Словарь из train делает «rule-based» частично основанным на данных.* Это стандартная часть
   rule-based систем (лексикон), но вклад разделён явно (dev): только правила — POS 76,2%, FEATS 68,4%;
   с лексиконом — 86,9% и 82,6%.
4. *Некоторые различия — соглашение разметки, а не грамматика*: *-ып* в KTB размечено то как
   `VerbForm=Conv`, то как `VerbForm=Inf`. Правила это различие не моделируют — ожидаемо слабое место,
   которое должен закрыть гибрид.
5. *Лемма* порождается грубо (отсечение аффикса) и не оценивается.

### 1.2 NER

**Что делает.**
1. *Шаблоны* (вручную): последовательность чисел (цифры или числительные словами) и следующее слово
   определяют тип: `%`/*пайыз*/*процент* → PERCENTAGE; валюта → MONEY; единица измерения → QUANTITY;
   *жыл…* или месяц → DATE; порядковое число → ORDINAL; иначе цифры или составное число → CARDINAL.
2. *Газеттир* из train: строка $x$, бывшая сущностью, получает самый частый тип и надёжность

$$r(x) = \frac{n_{\text{ent}}(x)}{n_{\text{ent}}(x) + n_{O}(x)}$$

   где $n_O$ — сколько раз та же строка в train не размечена. В газеттир входят строки с
   $n_{\text{ent}} \ge 2$ и $r \ge 0.5$. Последнее слово приводится к основе, если основа — известная
   сущность («Қазақстанның» → «қазақстан»), иначе берётся грубая основа, общая для падежных форм.
   Служебное слово становится сущностью только при $r \ge 0.8$ (в KazNERD *бүгін*, *биыл* — DATE).
3. Перекрытия: сначала шаблоны, затем газеттир, самые длинные совпадения первыми.

**Почему так.** Числовые типы почти полностью описываются формой (число + слово-индикатор), что даёт
высокую точность. Для именованных сущностей в новостях характерны повторяющиеся имена (Тоқаев,
Қазақстан, Үкімет), поэтому словарь с фильтром надёжности — сильная простая модель.

**Допущения и критика.** Газеттир не обобщает на новые имена (низкая полнота FACILITY, EVENT,
PRODUCT); граница сущности определяется словарём, а не синтаксисом; соглашения KazNERD (порядковые
числительные внутри дат) правилами передаются лишь частично (точность ORDINAL ≈ 0,47).

## 2. Нейросетевой метод

**Что делает.** Один предобученный трансформер (по умолчанию `xlm-roberta-base`; альтернатива —
`kz-transformers/kaz-roberta-conversational`) и линейные головы:

$$h_i = \text{Transformer}(x)_i, \qquad p_\theta\big(y_i^{(k)} \mid x\big) = \text{softmax}\big(W_k\, \text{dropout}(h_i) + b_k\big)$$

Головы: NER — 51 тег IOB2 (модель на KazNERD); UD — голова UPOS (17) и по голове на каждую
категорию FEATS (18 категорий, значение «_» = категории нет) — одна модель на UD-KTB решает
POS и морфологию. Слово получает предсказание своего **первого подслова**.

Обучение — сумма перекрёстных энтропий по головам (остальные подслова игнорируются):

$$\mathcal{L}(\theta) = \sum_{k} \sum_{i} w^{(k)}_{y_i} \cdot \big(-\log p_\theta(y_i^{(k)} \mid x)\big)$$

$w$ — веса классов (по умолчанию 1; для NER можно $w_c \propto 1/\sqrt{n_c}$ с ограничением 10).

| Параметр | NER (KazNERD) | UD (POS + FEATS) |
|---|---|---|
| Оптимизатор | AdamW, weight decay 0.01 | то же |
| Скорость обучения | 3e-5, линейный warmup 10% | 5e-5 |
| Эпохи / ранняя остановка | 3 / терпение 1 | 40 / терпение 6 |
| Батч / макс. длина | 16 / 256 подслов | 16 / 256 |
| Выбор эпохи | F1 на dev | (accuracy UPOS + exact FEATS) / 2 на dev |
| Seeds | 13, 42, 2026 | 13, 42, 2026 |

**Почему так.** Предобученные многоязычные трансформеры — текущий стандарт для разметки
последовательностей; общий «хребет» для всех задач — зафиксированное решение (decision log): оно делает
сравнение единообразным и экономит вычисления. FEATS по категориям вместо целой строки: в train 319
разных строк, треть встречается один раз — по отдельности категории обучаются на всех словах.

**Допущения и критика.**
1. *Предобучение переносится на казахский.* XLM-R видел казахские тексты, но их доля мала; поэтому
   сравниваются два «хребта» (решение открыто).
2. *Независимость категорий FEATS* (произведение вероятностей) — упрощение: модель может собрать
   несовместимый набор (например, `Tense` у существительного). Это одна из ошибок, которую исправляет гибрид.
3. *Первое подслово представляет слово* — стандартное, но не единственное решение.
4. *Маленький UD-KTB* (864 предложения): высокая дисперсия между seed — поэтому 3 seed и
   среднее ± стандартное отклонение; dev всего 107 предложений — выбор эпохи шумный.
5. *Гиперпараметры не подбирались полным перебором* (ограничение вычислений Colab) — взяты типичные
   значения для fine-tuning моделей base-размера.

## 3. Гибрид (основной вклад)

**Что делает.** Зафиксированная схема «Option B»: сначала нейросеть, затем коррекция правилами;
одинаково для всех задач.

*POS и морфология.* Для каждого слова:

1. **Жёсткие ограничения:** если правила распознали пунктуацию или число, берётся разбор правил.
2. **Мягкая коррекция:** среди кандидатов $Y = Y_\theta \cup Y_R$ выбирается

$$\hat{y} = \arg\max_{y \in Y} \Big[\log p_\theta(y \mid x) + \lambda \log q_R(y \mid x)\Big], \qquad q_R(y \mid x) = \frac{\exp s(y)}{\sum_{y' \in Y_R} \exp s(y')}$$

   где $s$ — оценки кандидатов анализатора, для $y \notin Y_R$ $q_R = \varepsilon = 10^{-4}$.
   Для FEATS по категориям $\log p_\theta(y) = \sum_k \log p_\theta(y_k)$.
   $\lambda = 0$ — чистая нейросеть, $\lambda \to \infty$ — правила. $\lambda \in \{0, 0.1, 0.25, 0.5, 1, 2, 4, 8, 16\}$
   выбирается на dev.

*NER.* Начиная с разметки нейросети:

1. сущность-шаблон правил с уверенностью $\ge \tau_p$ заменяет разметку, если средняя
   max-вероятность нейросети на отрезке $< \gamma$;
2. сущность газеттира с надёжностью $r \ge \tau_g$ добавляется, если нейросеть на отрезке ничего не нашла;
3. исправление IOB2.

$(\tau_p, \gamma, \tau_g)$ — по сетке $4 \times 4 \times 4$ на dev; значение 2.0 означает «компонент выключен».

**Почему так.** Нейросеть сильна в контексте, но ошибается на редких словах (OOV 41–45% в UD-KTB),
нарушает морфологические ограничения и путает числовые типы сущностей. Правила, наоборот, точны на
закрытых классах и регулярных формах. Логлинейная комбинация — минимальная формулировка «нейросеть
предлагает, правила корректируют» с одним параметром, который можно интерпретировать
(кривая $\lambda$ сохраняется в `outputs/hybrid/params_seed{N}.json`).

**Допущения и критика.**
1. *$q_R$ — не откалиброванная вероятность*, а softmax эвристических оценок; $\lambda$ компенсирует масштаб.
2. *Нейросети переуверены* — порог $\gamma$ по средней max-вероятности груб; калибровка (temperature
   scaling) не применялась.
3. *Подбор на маленьком dev UD-KTB (107 предложений)* может переобучиться; сетка намеренно грубая,
   а абляция показывает вклад каждого компонента.
4. *Коррекция покословная* (для POS/FEATS): согласование между словами не моделируется.

## 4. Оценка и статистика

**Метрики** (главная выделена):

$$P = \frac{TP}{TP + FP}, \quad R = \frac{TP}{TP + FN}, \quad F_1 = \frac{2PR}{P + R}$$

- NER: **micro-F1 по сущностям, strict** (тип и обе границы совпадают); также macro-F1 и F1 по типам.
- POS: **accuracy** по словам; macro-F1.
- Морфология: **exact match** (весь набор FEATS слова верен); feature-F1 по парам «категория=значение».

**Агрегирование.** Нейросеть и гибрид — 3 seed, в таблице среднее ± стандартное отклонение.

**Значимость.** Парный bootstrap по предложениям тестовой выборки ($B = 10\,000$):

$$p = \frac{1}{B} \sum_{b=1}^{B} \mathbb{1}\big[\, M(B_b) - M(A_b) \le 0 \,\big]$$

где $A_b, B_b$ — метрика методов на $b$-й выборке предложений с возвращением (одни и те же предложения
для обоих методов); статистика предложений усредняется по seed. Сообщаются разница, 95% доверительный
интервал и $p$ с **поправкой Холма** на все 9 сравнений (3 задачи × 3 пары методов).

**Разбивка ошибок** (`src/eval/breakdown.py`): известные и новые (OOV) слова/сущности, длина
предложения, исходный текст UD-KTB — проверка гипотезы о том, где гибрид помогает.

**Допущения.** Предложения теста независимы (bootstrap по предложениям); разница внутри задачи
интерпретируется, сравнение чисел между задачами — нет.

## 6. Открытые решения

- «Хребет»: XLM-R base или KazRoBERTa (сравнить на dev UD-KTB, один seed).
- FEATS: по категориям (по умолчанию) или целой строкой (`--morph-mode whole`).
- Веса классов для NER: нет (по умолчанию) или $1/\sqrt{n}$.
